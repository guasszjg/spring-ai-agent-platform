# 部署与运维

给负责打包、部署、升级平台的人看。

---

## 1. 环境要求

| 组件 | 要求 |
|---|---|
| JDK | 21 |
| 构建 | Maven 3.6+；前端需要 Node.js（构建 `spring_ai_ui`） |
| 数据库 | PostgreSQL 17，需要安装 **pgvector** 扩展（迁移会执行 `CREATE EXTENSION vector`、`pg_trgm`） |
| 框架 | Spring Boot 4.0 |

---

## 2. 构建与打包

前端（`spring_ai_ui`）构建产物直接输出到后端的 `src/main/resources/static/`，随 jar 一起发布。**前端有改动时，必须先构建前端，再打包后端**。

```bash
# 1. 构建前端（在 spring_ai_ui 目录）
npm run build

# 2. 打包后端（在 spring_ai 目录），会运行全部测试
mvn clean package
```

产物：`target/spring-ai-agent-platform-<版本>.jar`。

## 3. 配置与启动

### 3.1 配置文件与 profile

| profile | 用途 | 数据库结构 | 说明 |
|---|---|---|---|
| `dev`（默认） | 本地开发、测试 | `ddl-auto=update` | 自动加载 `application-local.properties`（数据库连接等，**不入库**）；允许内网模型地址；模型不可用时启用模拟回复 |
| `prod` | 生产 | `ddl-auto=validate` | 所有敏感配置从环境变量读取；禁止内网模型地址；不启用模拟回复；Cookie 仅 HTTPS |

`application-local.properties`、`application-secret.properties` 都在 `.gitignore` 里，**不要提交到仓库**（仓库是公开的）。

### 3.2 生产环境变量

| 变量 | 说明 |
|---|---|
| `DB_URL` | JDBC 连接串，例如 `jdbc:postgresql://<host>:5432/<db>` |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号 |
| `APP_CRYPTO_SECRET` | **密钥加密主密钥**，用来加密数据库里保存的模型 Key、向量 / OCR / Dify 凭证、自定义请求头等 |
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` | Spring AI 的兜底模型配置。实际对话走模型网关，这两项可以填任意兼容服务 |

> ⚠️ **`APP_CRYPTO_SECRET` 设定后不能改。** 改了之后，数据库里所有已加密的密钥都无法解密，需要在模型网关里逐个重新填写。请妥善备份。

### 3.3 启动

```bash
# 本地 / 测试
java -jar target/spring-ai-agent-platform-1.0.9.jar --spring.profiles.active=dev

# 生产（先设置好 3.2 的环境变量）
java -jar target/spring-ai-agent-platform-1.0.9.jar --spring.profiles.active=prod
```

默认端口 8080。控制台：`http://<host>:8080`。

### 3.4 其他常用配置（`application.properties`）

| 配置 | 默认 | 说明 |
|---|---|---|
| `spring.servlet.multipart.max-file-size` | 20MB | HTTP 层上传上限；知识库另有单文件 15 MB 的业务限制 |
| `server.servlet.session.timeout` | 30m | 控制台登录会话时长 |
| `app.assistant.rate-limit-per-minute` / `max-concurrent` | — | AI 助手的限流与并发 |
| `app.assistant.retention-days` | — | AI 助手会话保留天数 |
| `app.storage.local.root-dir` | — | 上传文件的本地存储目录 |

## 4. 数据库迁移（Flyway）

启动时 Flyway 自动执行 `src/main/resources/db/migration/` 下的迁移。

**规则（务必遵守）**：

1. **已经在任何环境执行过的迁移文件不能再修改。** Flyway 会校验文件校验和，改了之后后端直接启动失败。需要调整就新增一个版本（例如 V21 设了默认值，要改默认值就写 V22）。
2. **每个迁移都必须能重复执行**：用 `IF NOT EXISTS`、`ON CONFLICT`、条件 `DO` 块等写法。原因是 `baseline-version=0`：没有迁移历史的旧库会从 V1 开始全部重放一遍。
3. 改了实体字段，必须同步写迁移；否则 `prod`（`validate`）在新库上启动失败。

启动日志里可以看到迁移情况：`Migrating schema "public" to version "N - ..."`。

## 5. 首次部署检查清单

1. 启动后用超级管理员登录，**立即修改默认密码**。
2. **模型网关 → 大语言模型**：配置至少一个通道，测试连通，设为默认通道。按需设置降级备用并勾选自动故障转移。
3. **模型网关 → 向量模型**：配置并激活一个向量模型（自建知识库需要）。
4. （可选）**OCR 识别**：有扫描版 PDF 时配置。
5. （可选）**Dify 知识引擎**：需要对接 Dify 时配置。
6. **开放与安全 → 护栏策略**：设置敏感词、终端管控模式、默认限流。
7. **开放与安全 → 开放凭证**：按《开放接口接入指南》分用途签发凭证。

---

## 6. 运维注意事项

- **重启会让所有人掉线**：登录会话保存在内存里，后端重启后需要重新登录。
- **更换向量模型后要重建索引**：在知识库里重新索引已入库的文档。
- **凭证轮换**：轮换后旧 Key 有 24 小时宽限期，请在宽限期内通知接入方切换。
- **排查接口问题**：让对接方提供响应里的 `request_id`（响应头 `X-Request-Id`），到「审计日志」或服务日志中按 ID 查找。
