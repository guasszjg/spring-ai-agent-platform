# 开放接口接入指南

给对接方看：广告机等终端、你们自己的后台服务，或任何要通过接口调用平台的系统。

接口字段的完整说明以控制台「开放与安全 → 接入文档」为准（含在线调试）。本文讲接入流程、概念和容易踩的坑。

---

## 1. 接入流程概览

1. 在「开放与安全 → 开放凭证」**签发凭证**，勾选需要的权限与智能体范围。明文 Key 只在签发时显示一次。
2. （可选）在「接入终端」**登记终端**，并在「护栏策略」里设置终端管控模式。
3. 调用接口：`Authorization: Bearer <Key>`，基础地址 `https://<平台域名>/open/v1`。

只想让某个智能体能被对话调用时，也可以在该智能体调试页的「访问 API」里点「重新生成」，直接得到一把只限这个智能体、只有对话权限的 Key。

---

## 2. 凭证：权限与范围

所有接口用的是同一套「开放凭证」（`sk-live-…`），平台只保存哈希。**一把 Key 能做什么由两件事决定**：

**权限（scope）**

| 权限 | 能调用的接口 |
|---|---|
| `chat` | 对话 |
| `agents:read` | 查询智能体、查询其绑定的知识库 |
| `agents:write` | 创建 / 修改 / 删除 / 发布 / 暂停智能体 |
| `agents:bind_kb` | 给智能体绑定知识库 |
| `kb:read` | 查询知识库、文档、FAQ，检索召回 |
| `kb:write` | 创建 / 修改 / 删除知识库，上传 / 删除文档，增改删 FAQ |
| `conversations:read` | 查询会话与消息、删除会话 |
| `usage:read` | 用量统计、审计事件 |
| `account:read` / `account:write` | 账号信息、外部身份绑定 |

**智能体范围**：可以限定为若干个智能体，也可以不限（全部智能体）。凭证只能操作范围内的智能体。

### 按用途分开签发

| 用途 | 建议的凭证 | 放在哪里 |
|---|---|---|
| 终端对话（广告机等） | 只勾 `chat`，范围只选该终端用的智能体 | 终端设备 |
| 后台管理（建智能体、传文档） | `agents:*`、`kb:*` 等管理权限 | 只放在你们自己的服务端，不下发到终端 |
| 对账、报表 | `usage:read`、`conversations:read` | 报表服务 |

一把 Key 泄露时，影响范围只限于它的权限。

### 轮换与失效

- **轮换**：新 Key 立即生效，旧 Key 在 24 小时宽限期内仍可用，之后失效。宽限期内的响应会带 `X-Key-Status: ROTATING` 和 `X-Key-Grace-Expires` 响应头，可据此提醒切换。
- 凭证所属账号或签发人被停用、签发人权限变更后，相关 Key 自动失效，需要重新签发。
- 凭证可以设置过期时间和 IP 白名单。

## 3. 对话接口

```http
POST /open/v1/chat-messages
Authorization: Bearer sk-live-…
Content-Type: application/json

{
  "agent_id": "agent-xxxx",
  "message": "广告机怎么发布节目？",
  "response_mode": "blocking",
  "conversation_id": "",
  "user": "device-SN001"
}
```

| 字段 | 说明 |
|---|---|
| `agent_id` | 目标智能体 ID，也可以填智能体编码。**凭证范围只有一个智能体时可省略** |
| `message` | 用户问题（兼容 `query` 等别名） |
| `response_mode` | `blocking`：返回完整 JSON；`streaming`：SSE（默认 `streaming`） |
| `conversation_id` | 多轮对话时传上一轮返回的值，见第 5 节 |
| `user` / `end_user` | 终端用户标识，用于审计、用量统计和会话归属 |

**阻塞模式返回**（`data` 内）：`conversation_id`、`message_id`、`reply`、`model`、`tool_called`、`tokens_used`、`latency_ms`、`request_id`。

**流式模式**的事件：

| 事件 | 内容 |
|---|---|
| `message` | `answer` 为一段文本，依次拼接即为完整回答 |
| `message_end` | 结束，`metadata` 含 `model`、`tokens_used`、`latency_ms` |
| `guardrail` | 输出命中敏感内容，流式中断 |
| `error` | 模型调用失败 |

流式是**边生成边推送**：模型输出的文字经引用角标清理和输出护栏检查后立即发出，首字时间约等于模型的首字时间。智能体调用工具（如联网搜索）时，会先执行工具，再继续流式输出。

- 新会话的 `conversation_id` 从第一个 `message` 事件起就会带上，`message_end` 中的值为准。
- 输出护栏需要保留少量末尾文字做敏感词判断，所以推送会比模型略慢几个字。
- 使用「自定义 HTTP」协议的通道不支持流式，会在生成完成后一次性推送。
- 中途想停止：直接断开连接即可，平台会随之停止生成。`POST /open/v1/chat-messages/{taskId}/stop` 目前尚未实现，会返回 `not_supported`。

## 4. 接入终端（`X-Client-Id`）

终端管控由「护栏策略」的**终端管控模式**决定，默认是 **关闭**：

| 模式 | 不带 `X-Client-Id` | 带了但未登记 / 未批准 |
|---|---|---|
| 关闭（默认） | 放行 | 放行 |
| 只记录 | 放行，记审计 | 放行，记审计 |
| 强制 | 拒绝 `client_required` | 拒绝 `client_not_allowed` |
| 强制 + 自动登记 | 拒绝 `client_required` | 自动登记为待审批，本次拒绝，管理员批准后可用 |

请求头：

| 请求头 | 说明 |
|---|---|
| `X-Client-Type` | `SN` / `MAC` / `IMEI` / `APP_ID` / `CUSTOM_KEY`（默认 `CUSTOM_KEY`） |
| `X-Client-Id` | 终端唯一标识，需与登记的一致 |
| `X-End-User` | 可选，终端上的最终用户标识 |

终端还可以单独设置每分钟请求数和每日 Token 配额。广告机建议用 **SN + 强制模式**，便于管控和停用单台设备。

## 5. 多轮对话与上下文记忆

智能体有「上下文记忆」设置（`memoryTurns`，0～10 轮）：

- **默认 0（关闭）**：每次只发当前问题，最省 Token。适合 FAQ、知识库问答这类一问一答场景。
- **打开后**：调用方把上一轮返回的 `conversation_id` 带回来，平台自动带上该会话最近 N 轮问答，用户可以接着追问。
- **同一会话必须使用相同的 `user`**：平台只读取同一智能体、同一调用方的会话，别人拿到会话 ID 也读不到内容。
- 实际轮数不超过开发者护栏策略里的「最大历史轮数」。

记忆轮数在调试页「模型设置 → 上下文记忆」里调整，或通过 `POST /agents`、`PUT /agents/{id}` 的 `memoryTurns` 字段设置。每多带 1 轮，输入大约多 300～500 Token。

### 思考模式

智能体的「思考模式」（`thinkingMode`）决定是否让模型先思考再回答：

| 取值 | 行为 |
|---|---|
| `OFF`（默认） | 关闭思考：首字更快、输出 Token 更少，适合 FAQ、知识库问答 |
| `AUTO` | 不传思考参数，按模型默认（DeepSeek V4 默认会思考） |
| `ON` | 开启思考：复杂问题更严谨，但更慢 |

新建智能体（控制台手动创建、开放接口创建、AI 助手创建）不传 `thinkingMode` 时默认 `OFF`。可在调试页「模型设置 → 思考模式」调整，或通过 `POST /agents`、`PUT /agents/{id}` 的 `thinkingMode` 字段设置。部分中转通道会忽略这个开关。

## 6. 限流、配额与幂等

- **限流**：每把 Key 每分钟的请求数，优先用签发凭证时设置的「每分钟请求数」，未设置时用护栏策略的「默认 RPM」，都没有则 120 次。终端也可单独限流。超出返回 `429 rate_limited`，并带 `Retry-After`。响应头 `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset` 可用于自适应。
- **配额**：开发者（护栏策略）、单把凭证（签发时设置）和终端都可设每日 Token 上限，任一超出返回 `429 quota_exceeded`。用量统计有约 15 秒缓存，所以接近上限时可能略微超出。流式调用同样计入用量和配额。
- **幂等**：写操作（POST / PUT / DELETE）可带 `Idempotency-Key`，24 小时内同一 Key 重复请求直接返回首次结果（响应头 `X-Idempotent-Replay: true`），防止弱网重试导致重复创建或重复计费。

| 模块 | 接口 | 权限 |
|---|---|---|
| 对话 | `POST /chat-messages` | `chat` |
| 状态 | `GET /status` | 任意有效凭证 |
| 智能体 | `GET /agents`、`GET /agents/{id}` | `agents:read` |
| | `POST /agents`、`PUT /agents/{id}`、`DELETE /agents/{id}` | `agents:write` |
| | `POST /agents/{id}/publish`、`POST /agents/{id}/pause` | `agents:write` |
| | `GET /agents/{id}/knowledge-bases` | `agents:read` |
| | `PUT /agents/{id}/knowledge-bases` | `agents:bind_kb` |
| 知识库 | `GET /knowledge-bases`、`GET /knowledge-bases/{id}` | `kb:read` |
| | `POST /knowledge-bases`、`PUT /knowledge-bases/{id}`、`DELETE /knowledge-bases/{id}` | `kb:write` |
| | `GET /knowledge-bases/{id}/documents` | `kb:read` |
| | `POST /knowledge-bases/{id}/documents`（multipart）、`DELETE …/documents/{docId}` | `kb:write` |
| | `GET /knowledge-bases/{id}/faqs` | `kb:read` |
| | `POST …/faqs`、`PUT …/faqs/{faqId}`、`DELETE …/faqs/{faqId}` | `kb:write` |

## 8. 常见错误码

错误响应格式：`{"success": false, "message": "...", "data": {"code": "...", "request_id": "..."}}`。排查问题时请提供 `request_id`（也在响应头 `X-Request-Id` 里）。

| HTTP | code | 含义与处理 |
|---|---|---|
| 401 | `key_invalid` | 没带 Key、Key 不存在，或所属账号 / 签发人已停用 |
| 401 | `key_revoked` | 凭证已吊销或停用，或签发人权限变更，需要重新签发 |
| 401 | `key_expired` | 凭证过期，或轮换后超过 24 小时宽限期 |
| 403 | `scope_missing` | 凭证缺少该接口需要的权限 |
| 403 | `agent_out_of_scope` | 没指定智能体，或智能体不在凭证范围内 |
| 403 | `agent_not_running` | 智能体未处于运行状态（未发布或已暂停） |
| 403 | `ip_not_allowed` | 来源 IP 不在凭证白名单 |
| 403 | `client_required` / `client_not_allowed` / `client_expired` | 终端管控拦截，见第 4 节 |
| 403 | `kill_switch` | 该开发者的开放调用被紧急停用 |
| 403 | `outside_allowed_hours` | 不在护栏策略允许的调用时段 |
| 403 | `dependency_invalid` | 智能体绑定的知识库权限已失效 |
| 422 | 输入安全类 code | 输入命中护栏规则 |
| 429 | `rate_limited` / `quota_exceeded` | 限流或配额，见第 6 节 |

---

## 9. 关于 `/api/v1/chat-messages`

早期保留的兼容地址，与 `/open/v1` 走同一套安全检查（凭证状态、IP 白名单、终端管控、限流配额、幂等），行为一致。响应会带 `Deprecation: true` 头，新接入请一律使用 `/open/v1/chat-messages`。
